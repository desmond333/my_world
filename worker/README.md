# Прокси до TMDB

Воркер прячет ключ TMDB от браузера. Ключ хранится в секрете Cloudflare и никогда не попадает в код,
который видит пользователь. Браузер спрашивает воркер, воркер добавляет заголовок авторизации
и возвращает ответ TMDB.

## Зачем так

Vite встраивает переменные `VITE_*` прямо в бандл. Если задеплоить приложение с
`VITE_TMDB_TOKEN`, любой посетитель достанет твой ключ из devtools. Через воркер этого не происходит:
в бандле остаётся только адрес воркера.

С открытым токеном можно было бы только читать публичные данные о фильмах, но ключ всё равно
нельзя отозвать — при утечке пришлось бы ротировать и передеплоить.

## Что воркер делает

- пропускает только `/search/movie`, `/movie/{id}` и `/genre/movie/list`, поэтому он не превращается в открытый прокси к TMDB;
- сам задаёт `language=ru-RU` и `include_adult=false`, клиент эти параметры изменить не может;
- отсекает запросы короче 2 и длиннее 100 символов, номер страницы ограничивает десятью;
- `id` фильма проверяет по шаблону, нечисловые пути получают 404;
- кэширует жанры на сутки, результаты поиска на 10 минут, детали фильма на 6 часов;
- отдаёт `X-Cache: HIT` или `MISS`, чтобы было видно, работает ли кэш;
- на `OPTIONS` отвечает 204 с CORS-заголовками, а на неразрешённый Origin — 403.

## Настройка

Нужен бесплатный аккаунт Cloudflare.

```bash
cd worker
npm install
npx wrangler login
```

Создай секрет с ключом доступа к API из TMDB (вкладка API → ключ доступа):

```bash
npx wrangler secret put TMDB_TOKEN
```

Вставь токен, начинающийся на `eyJ`, и подтверди.

Задеплой:

```bash
npm run deploy
```

Команда напечатает адрес вида `https://today-animal-tmdb.<твой-поддомен>.workers.dev`.

## Подключение к приложению

В `.env` фронтенда:

```
VITE_TMDB_PROXY_URL=https://today-animal-tmdb.<твой-поддомен>.workers.dev
VITE_TMDB_TOKEN=
```

`VITE_TMDB_TOKEN` держи пустым в продакшене. Он нужен только для локальной разработки без воркера.

Переменные окружения для сборки задаются в настройках хостинга фронтенда, а не в файле.

## Локальная разработка

Два процесса в двух терминалах:

```bash
cd worker && npm run dev     # воркер на 127.0.0.1:8787
cd ..     && npm run dev     # приложение на 5173
```

Секрет для локальных запусков лежит в `worker/.dev.vars`, файл в `.gitignore` и в git не попадает.

## Ограничение по origins

По умолчанию `ALLOWED_ORIGIN = "*"`, воркер доступен любому. Своим друзьям это не мешает,
но чтобы воркер нельзя было использовать в чужих проектах, укажи в `worker/wrangler.toml`
адрес своего сайта:

```toml
[vars]
ALLOWED_ORIGIN = "https://my-site.pages.dev"
```

Несколько адресов перечисляются через запятую. Учти: заголовок `Origin` можно подделать обычным
curl, поэтому это защита от случайного использования, а не от целенаправленной атаки.

## Если ключ утёк

Настройки TMDB → API → перевыпустить ключ, затем `npm run secret` в папке воркера.
Новый секрет применяется сразу, передеплоивать фронтенд не нужно.
